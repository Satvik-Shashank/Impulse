Defense-Only Guardrails

GuardrailImplementation Detail
No Dispute GenerationSystem only responds to incoming dispute webhooks/payloads.
No PII Exposure100% synthetic data generated via Faker (Indian BFSI context).
No Raw Card DataCard numbers masked/tokenized; only match/no-match booleans evaluated.
Auditable Evidence RulesReason-code-to-evidence checklist is deterministic rule-table (card network spec compliant).
Kill SwitchSet AUTO_RESPOND_CONFIDENCE = 1.0 in response_generator.py to force 100% human review.

Documented Failure Modes & Edge Cases

The system is deliberately tested against cases it is expected to handle poorly, and its behavior in each case is documented rather than hidden.

Failure ModeSystem BehaviorArchitectural Rationale
Weak / Absent Evidence Routed to HUMAN_REVIEW, never auto-submitted Auto-submit requires both confidence threshold & minimum evidence strength gate.
Ambiguous Mixed-Signal Dispute Platt calibration keeps confidence low → routes to review Platt scaling ensures confidence represents true probability rather than arbitrary guess.
Unknown / Malformed Reason Code Falls back to generic.j2 template with auto_respond_eligible = False System fails closed, not open, on unrecognized inputs.
High-Value Dispute + Strong Evidence Subject to standard threshold logic (no special-casing) Prevents arbitrary human overrides when stakes are highest.
